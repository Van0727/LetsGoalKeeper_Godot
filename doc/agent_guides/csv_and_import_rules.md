# 配表与 CSV 资源规范

## 配表文件职责

- 项目策划配表统一存放在 `tables`。
- CSV 是数据源，`data` 下由导入工具生成的 `.tres` 和目录资源是运行时产物；修改数据时应优先修改 CSV，再运行统一导入工具，禁止只改生成资源导致两边不一致。
- 卡牌、战利品等正式数据必须通过现有导入器完成字段校验、资源生成和回读验证。
- 新增配表时，应同步提供中文说明行、字段名行和字段类型行，并在导入器中严格校验三行结构。

## Godot 导入方式

- `tables` 下用于策划数据的 CSV 不是本地化翻译表，对应 `.csv.import` 必须设置为：

  ```ini
  [remap]

  importer="keep"
  ```

- 禁止将策划配表设置为 `csv_translation`，否则 Godot 会把表头各列误认为语言并生成大量 `.translation` 文件。
- 修改或新增 CSV 后必须检查 Godot 实际导入器；不能仅凭文件扩展名推断导入方式。
- 配表目录中不应存在由策划 CSV 生成的 `.translation` 文件。若出现，应先把对应 CSV 改为 `importer="keep"`，再删除误生成文件并重新导入。
- 真正用于本地化的 CSV 应放入专门的本地化目录，不得与策划数据表混放。

## 编码、格式与字段契约

- 新增或修改含中文的策划 CSV 时统一保存为 UTF-8 BOM（前三字节 `EF BB BF`）；字段顺序和类型必须与导入器声明完全一致。既有未修改文件的编码迁移应单独验证，不得顺手批量重写。
- 写入后必须按 UTF-8 严格解码回读，检查 BOM、中文说明行及代表性名称或文案的实际字符。不能只看终端输出或仅检查是否含 `�`；错误转码也可能留下合法 UTF-8 的乱码。发现乱码应从可信原文或版本记录恢复，禁止猜测性批量转码。
- 包含逗号、换行或双引号的文本必须使用合法 CSV 转义，禁止依赖手工字符串拆分。
- 不得随意修改字段名、字段类型或列顺序；契约变化必须同步更新导入器、测试和相关文档。
- 数字字段必须明确范围和用途，导入时校验整数、枚举、上下限及唯一性。
- 文件名字段只能使用安全的资源名，不得包含路径跳转、扩展名或不稳定字符。

## 数字 ID

- CSV 第一列数字 `id` 是正式运行时唯一查找键；同类数据必须使用约定号段，并保证永久唯一。
- 已发布或进入存档的数据 ID 不得复用。资源被下架时应保留原 ID，使用禁用标记退出奖励池。
- 英文 ID 只允许作为资源文件关联、配表内部关联或旧存档迁移键；不得继续用于运行时查找、持有排重和特殊逻辑判断。
- 特殊玩法逻辑引用战利品时必须使用带语义名称的数字常量，禁止在业务代码中散落裸数字。
- 涉及存档的 ID 规则还必须遵守 [`save_compatibility.md`](save_compatibility.md)。

## 卡牌表专项契约

- `tables/cards.csv` 每个卡牌 ID 恰好一行并按数字 ID 升序排列。
- 卡牌通过 `effect_id` 复用 `tables/effects.csv` 中唯一的效果模板；`tables/effect_steps.csv` 按 `effect_id` 和 `effect_index` 升序定义模板步骤。
- 卡牌行数值列表逐项对应模板步骤，不得为多效果重复卡牌 ID 或复制模板步骤。

## 导入和修改流程

- 修改前确认目标 ID、号段、字段类型、资源路径、引用关系及受影响的存档契约。
- 修改后运行统一配表导入、生成资源回读校验、Godot 编辑器重新扫描或重新导入，以及对应领域的冒烟测试。
- 导入失败时不得继续使用部分生成结果；应检查是否发生部分写入，并重新执行完整导入。
- 导入后确认数据数量符合预期、ID 无重复或越界、引用目标存在、生成资源包含正确 ID 与中文文案、目录资源收录完整、禁用数据没有进入正式奖励池，且 `tables` 下没有误生成的 `.translation` 文件。

## 测试要求

- 每类配表至少覆盖正常导入、缺失文件、错误表头、重复 ID、越界值、无效引用和生成资源回读。
- 涉及存档 ID 时，覆盖新格式往返、旧格式迁移、重复旧值和无法映射值。
- 涉及奖励池时，覆盖数字 ID 查找、持有排重、禁用项过滤和无效 ID。
- 测试中的临时资源必须显式设置合法且不与正式数据冲突的测试 ID。
