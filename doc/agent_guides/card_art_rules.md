# 卡牌插画生成规范

## 生图前确认

- 必须先完整阅读并遵守 [`image_asset_rules.md`](image_asset_rules.md)。本文件只补充卡牌插画的领域约束；卡牌不使用通用绿幕流程。
- 同批素材先生成一张样张确认风格，再扩展其他卡牌。
- 卡框、费用、名称、类型、说明和数值均由 Godot 动态绘制，不得进入插画。

## 尺寸与文件

- 当前 `CardView/Canvas/Illustration` 显示槽为 `85.416664×79` 逻辑像素，卡内位置为 `(9, 16)`，比例约 `1.081:1`；游戏基准画面为 `360×640`。窗口缩放后的屏幕像素与逻辑像素必须区分。
- 最终素材统一为 `342×316` 像素、`171:158` 比例、PNG RGBA，约为显示槽的四倍分辨率。不得继续套用旧的 `200×150`、4:3 或 `176×132` 规格。
- 生图前重新核对实际槽位；比例变化时重新确定规格。先按目标比例生成，再高质量重采样至最终尺寸，不拉伸、不裁主体、不留无用边距。
- 插画保存到 `assets/ui/cards`。候选图使用版本后缀；用户确认前保留已接入资源，确认替换后再同步更新引用。

## 画风与配色

- 以已确认参考图与 `card_gloves_v5.png` 为画风基准：扁平移动端 UI 插画、大色块、清晰深蓝描边、少量干净的块面阴影和高光。参考图只约束画风与质感，不照搬配色、构图或足球素材。
- 保留明确色相，适度降低饱和度，明亮但不刺眼；“高级灰”表示克制的饱和度与配色，不代表灰色、去色、单色或压暗。
- 避免写实材质、布料纹理、颗粒、复杂缝线、复杂明暗、过度渐变、镜头光晕和电影化光效。

## 主体与光影

- 根据 `tables/cards.csv` 的名称和效果独立设计主体、轨迹与构图，不得仅换背景色或套用同一足球模板。主体足够大，以一个主要视觉主题为核心，不强制居中。
- 同图多个足球必须有不同球面朝向、旋转角度和透视大小，禁止复制同一个球再缩放；同批不同卡牌也不得机械重复球面布局。
- 统一左上受光、右下投影：物体左上有少量亮面，右下有侧面暗部，并向背景投下清晰克制的阴影。
- 高光、暗面和投影采用简洁块面与少量色阶；投影不得扩大画布、挤压主体或形成外围留白。
- 缩小到实际游戏尺寸后，主体、轮廓和光影层次仍须清晰；避免细线与高密度细节。

## 效果区分与运动形变

- 已确认的四张攻击牌方向：香蕉球为紫色背景与明显 C 形回弯；挑射为青蓝背景、高抛弧线与简化球门；连续射门为蓝色背景、多个球与独立速度拖尾；爆炸球为珊瑚橙背景、单球与集中爆裂块面。后续卡牌按自身效果设计，不套用这四种构图。
- 挑射保持自然圆球；香蕉球、连续射门和爆炸球可沿飞行方向轻微拉伸、倾斜，各球形变程度可不同，禁止全部圆球或全部统一压扁。
- 形变须克制且仍清楚是足球，不得成为橄榄球、蛋形或扁盘。球面、高光与暗部随形变调整；拖尾连接球后侧，避免悬停感。
- 用户要求局部修改时，只修改明确指定部分，锁定其余构图、配色和主体；未经批准不得借修补重新设计。

## 圆角与透明区域

- 生图阶段只生成完全不透明的直角矩形，背景铺满四边和四角，不使用绿幕；不得让模型生成透明、半透明、圆角面板或孤立主体贴纸。
- 原图验收并高质量缩小后，再用固定程序复制 `card_gloves_v5.png` 的 Alpha 蒙版切圆角；`342×316` 成品圆角半径约 `32` 像素，以手套实际轮廓为准，不让模型决定圆角。
- 最终四圆角面板外接边界与画布四边相切，不添加外围透明边距或阴影占位；用户明确暂不处理圆角时，交付完全不透明矩形 PNG。
- 面板内部 Alpha 必须为 `255`，仅四角外侧透明，轮廓边缘允许抗锯齿过渡；不使用绿幕，也不因旧绿幕规则禁止正常绿色配色。
- 禁止额外透明边距、内部镂空、黑色空洞、背景缺失或主体区域缺失。主体、拖尾、特效与投影均须位于面板内。

## 生成、接入与验收

- 原始生图逐像素检查完全不透明性，再目视检查背景缺色、黑洞与杂讯；坏图不得交付，禁止强制修改 Alpha 掩盖颜色缺失。
- 成品回读检查尺寸、颜色模式、内部 Alpha 为 `255`、透明仅在四角外侧、圆角与手套蒙版一致、有效内容无额外边距；在实际槽位尺寸核对球面差异、效果辨识度与形变幅度。
- 保存候选图不等于批准接入：用户确认前不覆盖已接入资源、不修改游戏引用；失败草稿不得混入正式交付文件。
- 接入时同步检查卡牌资源引用、场景纹理和 `@tool` 的 `editor_preview_definition`；工具脚本的 `configure()` 会覆盖场景纹理，不能仅修改 `TextureRect` 静态纹理就宣称预览已更新。
- 接入后完成 Godot 重新导入及真实场景渲染，检查显示范围、圆角、主体清晰度与光影。平滑插画使用线性过滤，避免最近邻过滤产生像素台阶；实际设置以当前 Godot 版本官方文档与运行验收为准。
- 配表导出必须保留已确认插画引用；CSV 未声明插画字段时，美术引用单独维护，不为换图擅改数值表契约，导出后回读确认引用未清空。
- 无法实际渲染时明确标注未验证项，不得仅凭路径、源图尺寸或节点配置宣称游戏内效果通过。
- 交付报告最终提示词、路径、尺寸、格式、裁切或缩放情况、Godot 重新导入结果、真实场景验证结果及未验证项。
