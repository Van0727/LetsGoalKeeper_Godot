# 图片生成、处理与 UI 参考图规范

本规范适用于所有游戏图片。怪物和卡牌任务还须读取对应专项文档；专项文档明确声明的差异优先于本规范。

## 生图前确认

- 生图前向用户明确说明目标用途、最终像素尺寸、宽高比例、文件格式、保存路径和是否裁切或缩放；未经确认不得调用图片生成工具。
- 同一需求包含多个素材时，逐项列出尺寸与用途；不得混用插画槽、整张卡牌或 UI 徽章尺寸。
- 先确定游戏中的实际目标槽位比例和最终像素尺寸；有效内容须顶住目标边框，不得保留无用边距、空白像素或只用于构图的外围留白。
- 图片模型不能直接输出目标小尺寸时，按相同比例生成，再高质量缩放至最终尺寸；项目中保存最终尺寸文件，不依赖运行时缩小模型原图。
- 生成图片不得包含未经要求的文字、数字、Logo、水印、卡框、按钮、费用标记或其他应由 Godot 动态绘制的 UI。

## 背景与抠图

- 除卡牌插画等专项规范已明确采用其他 Alpha 流程的素材外，默认使用纯 `#00FF00` 绿幕，不要求模型生成透明背景。
- 绿幕覆盖全部背景和四角，不得包含渐变、纹理、阴影、光晕或明显色差。
- 需要抠图的主体、描边、高光、反射和特效不得使用接近绿幕的绿色；边缘须清晰，避免绿色溢色。设计必须使用绿色时，先获得用户确认并改用可可靠分离的背景或透明流程。
- 抠图后检查孤立像素、锯齿杂点、无意义半透明残留和透明像素中的错误底色，避免过滤、缩放或 Mipmap 产生绿边或黑边。
- 用户完成抠图后，保持相同文件名、像素尺寸和资源路径覆盖；覆盖后触发 Godot 重新导入并验证引用未失效。

## 整屏参考图尺寸换算

- 从整屏参考图复刻 UI 时，先读取参考图原始像素尺寸，再测量目标元素的实际像素边界；不得凭视觉估算素材尺寸。
- 通用公式为：`目标宽度 = 参考元素宽度 × 目标屏幕宽度 ÷ 参考图宽度`，高度同理；横纵缩放比例存在微小截图误差时，结合目标槽位比例统一取整。
- 原战斗 UI 参考图为 `941×1672`；按当前目标视口重新计算，不得套用历史 `720×1280` 视口约 `0.765` 的系数或 `176×132` 示例。
- 截图换算得到的是运行时显示尺寸，不能证明源素材是否包含透明边距、九宫格边缘或高倍源图；交付分辨率须另行明确。

## 接入与交付

- 用户只批准候选图时不得覆盖正式资源或修改游戏引用。
- 覆盖同路径资源后必须触发 Godot 重新导入，并检查编辑器预览、运行时加载、实际显示尺寸、过滤方式和缺失回退。
- 交付报告最终尺寸、比例、格式、颜色模式、保存路径、生成提示词、裁切或缩放及 Alpha 处理情况、Godot 重新导入结果、实际场景验证结果和未验证项。
