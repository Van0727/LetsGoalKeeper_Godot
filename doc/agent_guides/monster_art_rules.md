# 怪物图片生成与接入规范

## 生图通用前置约束

- 必须先完整阅读并遵守 [`image_asset_rules.md`](image_asset_rules.md)。本文件只补充怪物图片的领域约束。
- 怪物源图默认沿用通用规范的纯 `#00FF00` 绿幕；用户明确批准直接透明图时才改用真实 Alpha 流程。

## 文件与画布

- 生图前核对目标场景中的实际显示槽、逻辑尺寸和宽高比例；不得把截图像素、编辑器缩放后的屏幕像素或其他素材规格直接套用。
- 正式怪物图片使用安全的数字图片 ID 命名，保存到 `assets/ui/enemies`，文件名与怪物配表 `image_id` 一致。候选图放在独立候选目录或使用明确版本后缀，用户确认前不得覆盖已接入资源。
- 正式成品为 PNG RGBA；画布和有效内容范围以当前槽位及同类已确认资源为准。主体、必要特效和动态元素须完整位于画布内，保留抗锯齿和动画安全边距，不得贴边、裁切或保留无关的大块空白。

## 视觉设计

- 怪物应与现有界面的精细度、形体概括和光影复杂度协调；规范约束视觉关系，不固定轮廓颜色、具体色相、物种、身体结构或装饰类型。
- 每只怪物应有易识别的整体轮廓、稳定视觉重心和少量明确标志。缩小到实际尺寸后，表情、主要形体与关键状态仍须清楚，避免依赖细线、微小纹理或高密度装饰。
- 配色建立清楚的主体、次要区域和强调区域关系，保证相邻形体及角色与战斗背景之间有足够区分；不得机械复用同一配色，也不得无依据地去色、压暗或单色化。
- 高光、暗面、投影和材质细节服务于形体识别，保持层级简洁；避免写实纹理、颗粒噪点、过度渐变、复杂反射和电影化光效。
- 动感可通过姿态、形变、重心、轮廓趋势、动态线或局部效果表达，具体方式服从角色设定；不强制音符、乐器、运动器材或固定身体部位。
- 参考图只约束用户明确要求的画风、观察角度、精细度或构图关系，不得未经要求复制具体配色、主题物件、角色结构和背景元素。

## 已确认扁平画风标准

- 第一章普通怪物以 `assets/ui/enemies/7001.png` 和已确认的乌龟扁平化方案为画风基准：扁平移动端插画、大色块、清晰深蓝描边、少量干净块面阴影和图形化高光。参考图只约束扁平程度、形体概括和渲染语言，不照搬造型与配色。
- 需要正视角时必须严格面对镜头：面部、胸腹和主要形体围绕垂直中轴组织，双眼同高且大小接近，两侧可见量与主要肢体落点近似对称；不得用偏头、侧脸、身体转向或三分之四透视替代。次要元素可轻微不对称，但不得破坏主体正视关系。
- 外轮廓使用清晰稳定的深蓝粗描边；内部只保留识别结构和表情所需线条。缩小后轮廓、表情和主要色块仍须清楚。
- 每种主要材质原则上使用约二至三个明确色阶，以纯色和边界清楚的块面塑形；禁止依赖连续柔和渐变、复杂环境反射、写实材质或密集色阶。
- 光影统一左上受光、右下暗面；高光为少量干净图形色块，暗面使用克制的块面阴影。不得出现大面积镜面高光、玻璃或塑料反射、电影化轮廓光或堆叠渐变。
- 配色保留明确主体色、辅助色和强调色，明亮但克制；扁平化不等于去色、灰化或压暗。只保留有助识别的斑点、纹理和装饰。
- 对已确认角色进行风格迁移时，只允许调整上色、光影、描边和细节密度；锁定观察角度、姿态、表情、比例、主体轮廓、配色关系和画布占比。改变任一项须先另行说明并获得确认。
- 第一章普通怪物正式成品统一为 `512×512`、PNG RGBA，为挤压、弹跳、旋转和震动保留安全边距。输出后检查四角透明、无绿幕残色，并在约 `205×153` 的实际战斗头像显示区分别以浅色和深色背景验证小尺寸辨识度。

## 第一章抽象圆团怪物

- 以 `assets/ui/enemies/7001.png` 的形体语言为首要参考：主体概括为圆团、半圆、圆盾或其他单一几何大轮廓，五官嵌入主体，不默认补全真实动物躯干。参考圆润比例、大五官、紧凑轮廓、少量圆形高光和图标化辨识度，不照搬鸡的配色、冠羽或翅膀。
- 物种识别原则上只保留二至四个关键符号；删除与小尺寸识别无关的肌肉、关节、手脚细节、写实皮毛、密集甲片和复杂服装。非核心四肢弱化为短小圆形附属块或隐藏。
- 抽象不等于同一圆球换色。同批怪物通过宽高比、外轮廓趋势、视觉重心和标志器官形成实质差异；不得统一套用直立人形、双拳撑地、交叉手臂或完整兽人骨架。
- 动作优先通过主体倾斜、挤压、局部形变、轮廓方向和少量粗动态线表达，避免复杂肢体表演。
- 正视角要求继续适用；轮廓、附属块和动态线可轻微不对称以表达动作，但不得破坏主体正面关系。
- 光影使用大面积顺滑色块、约二至三个明暗层级和少量圆润高光，保持轻盈图标质感；不得添加写实材质、细碎毛发、复杂反射、电影化轮廓光、背景光晕或大量渐变。
- 每只怪物建立独立的主体色、辅助色和强调色；深蓝描边、表情和主要物种符号缩小后保持清楚。未经设定要求，不得以护腕、盔甲、服装或运动器材代替轮廓设计。
- 门神或大型封锁型怪物优先使用宽扁、横向展开的主体轮廓；除非用户明确要求，不得生成人形站姿、张开手掌或写实守门员动作。

## 背景、抠图与边缘

- 绿幕必须覆盖全部背景和四角并保持纯色。用户批准透明图时，成品必须具有真实 Alpha，不得以黑底、白底或棋盘格伪装。
- 抠图保留主体及确认的动态元素，清除绿幕溢色、孤立像素、锯齿杂点和无意义半透明残留；不得通过粗暴扩大或缩小 Alpha 掩盖问题，也不得误删有效内容。
- 正式 PNG 的完全透明区域不得残留在线性过滤、缩放或 Mipmap 后形成绿边、黑边的错误颜色。接入前在透明、浅色和深色背景分别检查边缘。

## 提示词结构

- 按“用途与槽位、主体概念、性格与行为、整体轮廓、观察角度与构图、视觉表现、配色关系、动感或特效、背景、禁止内容”组织提示词，各项使用当前需求的可替换描述。
- 明确实际用途和小尺寸可读性，要求主体占据合理范围、有效内容完整且无无用留白，并禁止未经要求的文字、数字、Logo、水印、UI、边框、平台、复杂场景和无关元素。
- 同批方案通过轮廓、重心、表情、姿态、配色关系或标志特征形成实质差异，禁止只换色或少量装饰。

## 动画适配

- 整图程序动画要求主体轮廓、表情区域和必要动态元素清楚且不过度遮挡，画布为挤压、弹跳、旋转和震动保留安全范围；不得为预设动画擅改已确认构图。
- 分层、骨骼或逐帧动画须在生图前另行确定分层边界、遮挡关系、关节覆盖、帧数和导出规格。
- 眨眼、局部形变等坐标依赖效果按怪物单独配置并提供安全关闭方式，不得假定结构或表情位置一致。

## 接入与验收

- 接入优先修改图片源文件及正式数据源：将图片 ID 写入怪物 CSV 后运行统一导入器，回读生成资源并确认 `image_id`。禁止只改 `.tres` 或在场景叠图规避正式引用。
- 覆盖同路径图片后触发 Godot 重新导入，并检查编辑器预览、运行时加载、实际显示尺寸、过滤方式和缺失回退。源图分辨率正确不能代替真实场景验收。
- 回读检查 PNG 格式、像素尺寸、RGBA、Alpha 有效边界、四角透明、主体安全边距、异常半透明像素和边缘颜色；再以实际游戏尺寸检查辨识度、裁切、遮挡、锯齿和背景对比。
- 用户只批准候选图时不得修改游戏引用；确认接入后保持图片 ID、文件名和路径稳定。改变规格或路径前说明受影响的配表、预览、缓存和运行时加载范围。
- 用户完成抠图后，以相同文件名、尺寸和路径覆盖，并触发 Godot 重新导入及引用验证。
- 交付报告最终尺寸、格式、路径、提示词、裁切或缩放情况、Godot 重新导入结果、实际场景验证结果及未验证项。
