# Godot 实施与验收规范

## 实施前检查

- Godot API、编辑器行为、资源加载、导入机制或版本兼容性不确定时，先查询项目对应版本的 Godot 官方文档并记录依据，不得依赖记忆连续试错。
- 确认修改范围、资源路径、场景和脚本依赖、`@tool` 依赖链、编辑器缓存或重启要求、数据边界、类型转换、失败后的部分写入风险及存档兼容性。
- 修改生成资源前确认其正式数据源；能从 CSV 或源资源生成的内容不得只修改产物。

## 风险对应的验证

- 所有变更至少覆盖正常路径、关键边界和失败路径。
- 代码行为变化运行对应单元或冒烟测试；资源或场景变化同时检查加载、缺失回退和实际显示。
- `@tool` 或编辑器预览变化必须验证工具脚本的实际覆盖顺序，不能只检查场景文件中的静态属性。
- 导入流程变化必须检查重新扫描或重新导入、生成结果回读、缓存影响及失败后是否留下部分产物。
- 配表验证遵守 [`csv_and_import_rules.md`](csv_and_import_rules.md)；存档相关验证遵守 [`save_compatibility.md`](save_compatibility.md)。
- 图片接入还须遵守对应的怪物或卡牌专项规范，并在实际目标槽位检查过滤方式、裁切、遮挡、锯齿和背景对比。

## 结果报告

- 逐项列出实际运行的命令、场景或手工检查及其结果。
- 无法运行 Godot 或真实场景时，明确写出未验证项和原因，提供可复现步骤，不得以路径存在、源图尺寸正确或静态配置正确代替运行验证。
- 测试失败时说明失败范围、可见证据和是否可能存在部分写入；不得把未运行或失败的测试表述为通过。
