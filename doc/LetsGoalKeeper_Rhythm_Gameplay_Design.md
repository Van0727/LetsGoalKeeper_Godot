# LetsGoalKeeper 节奏玩法设计文档

> 用途：定义回合制卡牌战斗与节奏判定结合后的目标体验、首版范围、规则边界和后续扩展方向。
>
> 文档状态：概念设计与 MVP 实施基准。标记为“待验证”或“待确认”的内容，需要通过可玩版本和玩家测试后决定。
>
> 首版原则：先验证“拖牌、听拍、松手、立即得到反馈”是否有趣，不同时引入曲风卡组、复杂连击、Boss 变速等外围系统。

> 实施状态（2026-09-08）：核心 MVP 已接入。战斗使用 `sound/beats/basicDrum_2.mp3`，当前按 100 BPM、4/4 拍、首拍偏移 0 秒循环；已完成音频时钟、拖牌松手判定、节拍 UI、Miss 对敌伤害减半和自动化测试。节奏盾及曲风系统仍未实现。

## 1. 玩法概述

在现有 Roguelike 卡牌战斗中加入节奏操作。每场战斗播放具有明确 BPM 的背景音乐，玩家把卡牌拖过出牌线后，在节拍点上松手即可完成一次节奏出牌。

节奏准确度会改变本次卡牌的结算效果：准确出牌获得完整效果，偏离节拍则受到效果衰减。界面、角色和足球反馈跟随音乐脉冲，使听觉、操作和战斗结果形成统一反馈。

长期目标包括：

- 不同敌人拥有自己的音乐、BPM 和节奏特征。
- 连续准确出牌形成节奏连击或触发特殊效果。
- 章节场景对应不同曲风。
- 卡牌或牌组拥有 Hip-hop、Rock、Acoustic、MIDI 等曲风标签。
- 曲风与当前战斗音乐产生适配、克制或混音效果。
- 准确结束回合获得节奏防御。
- 地图、房间和战斗之间使用切歌、打碟或过门音效衔接。
- Boss 转阶段时改变编曲、节拍密度或 BPM。

## 2. 设计目标

### 2.1 核心体验

- 保留回合制卡牌的思考空间，同时让每次出牌具有即时操作感。
- 玩家能够通过听觉和视觉预判节拍，而不是依赖随机判定。
- 节奏表现与伤害反馈发生在同一次操作中，形成明确的因果关系。
- 非节奏玩家也能理解失败原因，并能通过宽松难度或校准功能正常游玩。
- 核心系统支持后续增加敌人音乐、切分音、曲风卡组和 Boss 多阶段，而不必重写出牌流程。

### 2.2 非目标

首版不追求完整音乐游戏深度，也不制作谱面编辑器。节奏系统用于强化卡牌战斗，不取代卡组构筑、能量规划、敌人意图和 Roguelike 成长。

## 3. 更新后的战斗循环

1. 进入战斗并加载敌人对应的音乐配置。
2. 音乐开始播放，战斗界面显示稳定的视觉节拍。
3. 玩家选择卡牌并拖过出牌线。
4. 玩家在目标节拍附近松手。
5. 系统以松手时刻计算 `Perfect`、`Good` 或 `Miss`。
6. 界面立即显示判定等级与时间误差。
7. 卡牌支付能量，并携带本次节奏结果进入结算。
8. 伤害效果应用节奏倍率，多段伤害共用一次判定。
9. 足球动画和受击反馈表现最终结算结果。
10. 玩家继续出牌，或主动结束回合。
11. 后续版本中，准确结束回合可以获得一次节奏防御。

## 4. 首版 MVP 范围

### 4.1 必须实现

- 战斗内播放一首具有稳定 BPM 的测试音乐。
- 使用固定 BPM 和首拍偏移建立节拍时钟。
- 战斗界面显示简单的节拍脉冲和下一拍提示。
- 玩家有效拖牌并松手时进行一次节奏判定。
- 显示 `Perfect`、`Good`、`Miss` 和本次误差毫秒数。
- `Perfect` 与 `Good` 使用完整伤害，`Miss` 伤害减半。
- 节奏倍率仅影响玩家卡牌对敌人造成的伤害。
- 一张多段攻击卡只判定一次，全部伤害段使用相同倍率。
- 暂停、恢复或切出应用后，音乐、视觉节拍与判定仍保持同步。
- 使用自动化测试覆盖判定边界和伤害倍率。

### 4.2 暂不实现

- 准确结束回合获得节奏盾。
- 节奏连击和断连规则。
- 不同敌人的独立音乐资源。
- 曲风标签和曲风卡组。
- 章节动态混音。
- Boss 阶段切歌或动态 BPM。
- 八分音符、切分音、弱拍和人工谱面。
- 地图界面的 DJ 转场音效。
- 节奏相关 Roguelike 遗物和能力升级。

## 5. 卡牌节奏判定

### 5.1 判定时机

节奏判定发生在玩家松开鼠标或触摸的瞬间，并且只有卡牌已经越过有效出牌线时才结算。

以下时机不能用于判定：

- 卡牌开始拖拽时。
- 卡牌越过出牌线时。
- 卡牌飞行动画开始或结束时。
- 足球命中敌人时。
- 伤害数字出现时。

动画帧率可能波动，只有真实输入事件的时间能代表玩家操作。

### 5.2 音频时钟

判定应以音频播放位置为基础，不使用逐帧累加的普通计时器。概念公式如下：

```text
判定音乐时间
= 音频播放位置
+ 距离上次音频混音经过的时间
- 音频输出延迟
+ 玩家输入校准偏移
```

音乐配置至少需要以下数据：

| 字段 | 含义 |
| --- | --- |
| `music` | 战斗音乐资源 |
| `bpm` | 每分钟拍数 |
| `first_beat_offset` | 音频开头到第一个有效拍点的秒数 |
| `beats_per_bar` | 每小节拍数，首版默认 4 |
| `judge_subdivision` | 可判定的拍子细分，首版只判四分音符 |

仅记录 BPM 不够。音频可能包含开头静音、前奏或弱起，因此必须提供首拍偏移。

### 5.3 最近拍点计算

```text
每拍时长 = 60 / BPM
相对时间 = 当前音乐时间 - 首拍偏移
拍内位置 = 相对时间 % 每拍时长
节拍误差 = min(拍内位置, 每拍时长 - 拍内位置)
```

判定必须同时接受目标拍点之前和之后的输入。例如提前 50ms 与延后 50ms 应得到相同等级。

### 5.4 首版判定窗口

| 等级 | 绝对误差 | 伤害倍率 | 表现建议 |
| --- | ---: | ---: | --- |
| `Perfect` | `0～60ms` | `1.0` | 金色文字、强脉冲、清晰音效 |
| `Good` | `60～140ms` | `1.0` | 蓝绿色文字、普通脉冲 |
| `Miss` | `>140ms` | `0.5` | 灰红文字、轻微失拍反馈 |

这些窗口是首版建议值，必须通过键鼠、触屏、扬声器和蓝牙耳机实测调整。

`Perfect` 与 `Good` 首版使用相同伤害，是为了先验证手感，并保留等级反馈数据。后续可以让 `Perfect` 提供额外连击、资源或特殊触发，而不是简单堆高伤害。

### 5.5 节奏结果数据

节奏判定不应只返回“成功/失败”。建议保留结构化结果：

```gdscript
{
    "grade": PERFECT,
    "error_ms": -43.0,
    "absolute_error_ms": 43.0,
    "effect_multiplier": 1.0,
    "beat_index": 17,
    "bar_index": 4,
}
```

其中带符号误差可用于分析玩家习惯：负值表示提前，正值表示延后。该数据以后可以服务于延迟校准、连击、统计、回放和教程提示。

## 6. 卡牌效果规则

### 6.1 首版规则

- 只缩放玩家卡牌对敌人造成的直接伤害。
- 治疗、护盾、能量、抽牌、概率和状态持续时间不受影响。
- 多段攻击的每一段都使用同一次出牌判定倍率。
- 随机射门的弹道选择不改变节奏判定。
- 敌人反伤不受玩家本次节奏倍率影响。
- 主动技能暂不进行节奏判定。
- 非拖拽的调试攻击接口不使用节奏倍率。

### 6.2 长期效果策略

后续可为每项卡牌效果增加独立策略：

| 策略 | 含义 |
| --- | --- |
| `IGNORE` | 不受节奏影响 |
| `SCALE_AMOUNT` | 按节奏倍率缩放数值 |
| `BONUS_ON_PERFECT` | Perfect 时追加奖励 |
| `TRIGGER_ONLY_ON_BEAT` | 只有卡准才触发 |
| `CHANGE_ON_MISS` | Miss 时替换为另一种效果 |

不建议把所有效果统一减半。持续 1 回合、获得 1 点能量或抽 1 张牌都无法自然减半，容易产生大量隐藏取整规则。

## 7. 视觉与声音反馈

### 7.1 节拍指示

首版建议在战场中部或出牌线附近显示一个循环收缩的节拍环：

- 环在两拍之间逐渐收缩。
- 到达中心时代表目标拍点。
- 拍点瞬间背景、出牌线和角色产生轻微脉冲。
- 卡牌越过出牌线后，提高节拍环亮度并显示“跟随节拍松手”。
- UI 动画只负责提示，不能作为核心判定时钟。

### 7.2 判定反馈

松手后应立即显示判定，而不是等足球命中：

- 判定文字出现在卡牌释放位置或战场中心。
- 显示可选的 `早 43ms`、`晚 76ms`，帮助玩家理解节奏。
- Perfect 使用更强的出牌音效和屏幕脉冲。
- Miss 不应产生过强的羞辱或中断，避免玩家因一次失败失去操作节奏。

### 7.3 音乐关闭时

需要明确无音乐模式：

- 仍保留视觉节拍与节拍提示音；或者
- 自动关闭 Miss 惩罚；或者
- 提供“休闲节奏模式”，扩大判定窗口。

该规则与无障碍设置相关，不能简单把背景音乐音量视为纯表现选项。

## 8. 架构与模块边界建议

### 8.1 节拍时钟

新增独立节拍时钟模块，负责：

- 加载音乐配置。
- 启动、暂停、恢复和停止音乐。
- 计算当前音乐时间和拍位。
- 在输入发生时返回节奏结果。
- 向 UI 发出拍点信号。
- 应用设备或玩家校准偏移。

节拍时钟不负责卡牌费用、伤害或动画。

### 8.2 拖拽卡牌

拖拽卡牌模块继续负责：

- 鼠标和触摸拖拽。
- 有效出牌区域判断。
- 报告松手事件。

它不应直接读取音乐、BPM 或计算伤害，避免输入组件和战斗规则耦合。

### 8.3 战斗界面

战斗界面负责：

- 在有效松手时向节拍时钟请求判定。
- 显示节拍和判定反馈。
- 将节奏结果随卡牌一起传入战斗控制器。
- 协调输入锁与结算动画。

### 8.4 战斗控制器与效果执行器

- 战斗控制器验证回合、费用和卡牌合法性，并保存本次出牌上下文。
- 效果执行器只对标记为可缩放的伤害读取 `effect_multiplier`。
- 节奏结果应作为本次出牌的只读上下文，不写回卡牌 Resource。
- 音乐和 UI 不应成为核心伤害计算的依赖，测试可直接注入固定节奏结果。

## 9. 准确结束回合与节奏盾

该功能安排在第二阶段实现。

### 9.1 建议规则

- 玩家在节拍点按下结束回合，获得 1 层节奏盾。
- 节奏盾抵挡下一次敌方行动中的第一段直接攻击，然后消耗。
- Miss 时正常结束回合，不获得节奏盾。
- 节奏盾不抵挡反伤、持续伤害或玩家卡牌造成的自伤。
- 新玩家回合开始时，未消耗的节奏盾是否保留需要进一步测试；建议首版不叠加，最多 1 层。

### 9.2 不复用普通护盾

现有护盾按数值吸收伤害；节奏盾按攻击次数抵挡，两者语义不同。节奏盾应使用独立状态，例如 `rhythm_guard_charges`，不能简单添加一个很大的普通护盾值。

若敌人进行多段攻击，需要明确：

- 抵挡第一段攻击；或
- 抵挡整个敌人行动。

建议默认抵挡第一段，后续 Roguelike 能力可以升级为抵挡整次行动。

## 10. 关键设计风险

### 10.1 无限等待会拖慢回合

回合没有倒计时，玩家可以把牌拖到出牌线外无限等待下一拍。这降低操作难度，却增加无意义等待。

可能的解决方案：

- Miss 保留基础伤害，准确出牌只提供奖励。
- 卡牌越线后开启有限的节奏窗口。
- 等待过久会使节奏连击衰减。
- 让连续出牌形成乐句，奖励保持流动而不是单次等待。

第一版保留自由等待，以便单独测试基础触感；测试时必须记录它是否明显拖慢战斗。

### 10.2 惩罚可能过重

Miss 伤害减半会让节奏能力压过卡组构筑，也可能使听障玩家、静音玩家和高延迟设备玩家处于永久劣势。

需要对比测试两个版本：

- 惩罚制：Perfect/Good 为 100%，Miss 为 50%。
- 奖励制：Miss 为 100%，Good 为 110%，Perfect 触发额外奖励。

设计倾向：长期版本优先奖励制；MVP 按原始构想实现惩罚制，以验证差异是否足够明显。

### 10.3 输入与输出延迟

设备延迟可能使玩家稳定提前或延后。必须考虑：

- 蓝牙耳机音频延迟。
- 移动设备触摸采样延迟。
- 不同屏幕刷新率。
- 音频缓冲区大小。
- 系统卡顿和掉帧。
- 玩家自身的稳定提前或延后习惯。

正式版本应提供节奏校准页，并允许保存玩家偏移值。

### 10.4 暂停与失去焦点

暂停、切后台或打开覆盖层时必须同时暂停音乐与判定时钟。恢复后不能用系统经过时间直接补算，否则视觉和音乐会错拍。

### 10.5 音乐循环接缝

循环音乐必须在小节边界无缝循环。若音频文件带编码留白或循环点不准，长时间战斗会出现节拍跳变。正式资源需要记录有效循环起点和终点，而不是假设整个文件都可循环。

### 10.6 音乐版权与资源体积

每个敌人独立 BGM 会显著增加制作成本、版权管理和安装包体积。长期可以采用：

- 同章节共享基础音乐，不同敌人叠加独立乐器层。
- 普通敌人共享曲目，精英和 Boss 使用变体。
- 使用短循环和程序化分层，而不是每个敌人一首完整歌曲。

## 11. 难度与无障碍设置

建议预留以下设置：

| 设置 | 作用 |
| --- | --- |
| 判定难度 | 调整 Perfect 和 Good 窗口 |
| 输入偏移 | 补偿玩家操作习惯和触摸延迟 |
| 音频偏移 | 补偿输出设备延迟 |
| 视觉节拍 | 开关屏幕脉冲与节拍环 |
| 节拍提示音 | 在背景音乐之外强化拍点 |
| 减弱动态效果 | 降低整体 UI 缩放、闪烁和镜头震动 |
| 休闲节奏模式 | Miss 不降低基础效果 |

节拍脉冲需避免高频闪烁，并遵守减少动态效果设置。

## 12. 后续扩展方向

### 12.1 节奏连击

- 连续 Good 或 Perfect 增加节奏连击。
- Miss 断连或降低连击等级。
- 每个小节内连续出牌形成一个乐句。
- Perfect 连击可强化现有卡牌类型连击，但两者应使用不同名称和状态，避免玩家混淆。

### 12.2 曲风卡牌与牌组

卡牌可增加曲风标签：

- Hip-hop：强调重拍、连击和节奏稳定性。
- Rock：强调高伤害、连续快速出牌和强拍爆发。
- Acoustic：强调防御、治疗和宽松判定。
- MIDI / Electronic：强调切分音、能量变化和效果复制。

曲风不宜仅提供固定克制倍率。更有表现力的做法是改变节拍目标或 Perfect 奖励，让不同牌组真的拥有不同演奏手感。

### 12.3 敌人节奏个性

敌人可通过以下参数形成差异：

- BPM。
- 强拍位置。
- 可判定的节拍细分。
- 特殊小节长度。
- 节奏干扰表现。
- 对特定曲风的反应。
- 转阶段条件和音乐段落。

不能只用“更快 BPM = 更难”。慢速音乐中的切分音、停顿和弱拍也可以制造难度。

### 12.4 Boss 阶段变化

Boss 转阶段优先采用预制且同步的音乐层或段落：

- 在小节边界切换。
- 保持统一音乐时间轴。
- 改变鼓组、低音或旋律密度。
- 必要时切换 BPM，但提前向玩家提供过渡小节。

不建议运行时直接改变整首音频播放速度，这会影响音高、循环点和判定稳定性。

### 12.5 地图与房间转场

- 地图界面播放低密度基础循环。
- 选择房间时播放唱盘启动、切歌或滤波过门。
- 进入战斗后在小节边界加入敌人主题层。
- 胜利时播放与当前节拍对齐的收尾音效。

## 13. 测试与验收

### 13.1 自动化测试

- BPM 转换为每拍时长正确。
- 首拍偏移前后的拍点索引正确。
- 提前和延后相同毫秒数得到相同等级。
- `60ms`、`140ms` 等边界值判定一致。
- 音乐循环后拍点连续。
- 固定节奏结果能够稳定复现固定伤害。
- Miss 只缩放玩家对敌伤害。
- 多段伤害共用同一倍率。
- 治疗、护盾、能量和状态不被错误缩放。
- 暂停期间不能产生节奏判定，恢复后不漂移。

### 13.2 手动验收

- 键鼠与触摸都能稳定完成拖牌松手。
- 玩家只看视觉提示也能理解目标拍点。
- 玩家只听音乐也能完成基本判定。
- 判定反馈在松手后立即出现。
- 足球动画延迟不会改变已经得到的判定。
- 连续游玩至少三分钟后音乐与 UI 无明显漂移。
- 蓝牙耳机下可以通过校准获得合理判定。
- 低帧率下核心判定不依赖 UI 动画帧。

### 13.3 MVP 成功标准

满足以下条件才进入节奏盾和敌人独立音乐阶段：

- 玩家能够在短教程后理解松手卡拍。
- 节奏判定与主观听感基本一致。
- 节奏操作没有明显破坏拖牌可靠性。
- 等拍没有让单回合时间增加到不可接受。
- Miss 惩罚不会使普通战斗难度失控。
- 测试者愿意主动追求 Perfect，而不是忽略节奏系统。

## 14. 待确认事项

- 长期采用惩罚制还是奖励制。
- Good 是否与 Perfect 使用相同倍率。
- 首版测试音乐的 BPM、首拍偏移和循环区间。
- 玩家拖牌但未越线时是否显示节奏反馈。
- 主动技能是否也需要独立的节奏输入。
- 节奏盾抵挡第一段攻击还是整个敌人行动。
- 节奏连击与现有同类卡牌连击如何同时展示。
- 战斗音乐停止或静音时采用何种无障碍规则。
- 玩家延迟校准存入全局设置还是仅在当前设备有效。
- 后续使用纯 BPM 网格、人工 beat map，还是二者混合。

## 15. 推荐实施顺序

1. 独立节拍时钟与纯逻辑测试。
2. 单首测试音乐和战斗节拍指示。
3. 有效松手时生成结构化节奏结果。
4. 仅对玩家卡牌伤害应用倍率。
5. 补充即时判定反馈和调试误差显示。
6. 在真实设备上调整判定窗口和延迟补偿。
7. 对比惩罚制与奖励制。
8. 验证通过后实现准确结束回合与节奏盾。
9. 增加敌人音乐配置和不同 BPM。
10. 最后再扩展节奏连击、曲风卡组和 Boss 动态音乐。
