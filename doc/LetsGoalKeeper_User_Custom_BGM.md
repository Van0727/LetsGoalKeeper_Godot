# 用户自定义 BGM 功能说明

## 1. 功能目标

允许玩家在本地选择自己的音乐作为战斗背景音乐。游戏读取曲目的节奏信息，以该节奏驱动战斗内的拍点、判定窗口和相关演出；玩家也可以校正自动识别结果。

本功能的目的包括：

- 不随游戏安装包分发第三方音乐，降低内置音乐的授权压力。
- 让玩家使用自己喜爱的音乐，提升重复游玩的意愿。
- 让战斗节奏不再限定于开发者预置曲库。

## 2. 范围与非目标

### 本期范围

- 从玩家设备选择本地音频文件。
- 导入并在游戏内管理自定义曲目。
- 自动推测 BPM，并允许玩家确认和校正。
- 记录首拍偏移，使战斗拍点与音乐实际重拍对齐。
- 在战斗中按选定曲目的节奏运行。

### 非目标

- 不提供在线上传、云端存储、曲目分享或公共曲库。
- 不提供音乐版权检测、购买或分发服务。
- 不保证自动识别能正确处理所有曲风、变速歌曲或无明显鼓点的音乐。
- 不改变原有内置 BGM 的资源目录和播放逻辑；内置 BGM 仍遵循 `sound/bgm` 目录约定。

## 3. 用户流程

1. 玩家在“自定义 BGM”页面点击“导入音乐”。
2. 玩家从设备中选择一个本地音频文件。
3. 游戏校验格式、可读性和大小，并将文件复制到游戏的用户数据目录。
4. 游戏分析音乐，给出建议 BPM 和可信度。
5. 玩家可试听，并选择“减半”“加倍”、手动输入 BPM，或点击预览中的第一拍来校正首拍偏移。
6. 玩家保存曲目配置，在战斗前选择该曲目。
7. 战斗开始后，统一节拍时钟以曲目的 BPM 与首拍偏移计算当前拍点。

## 4. 支持格式与文件存储

初版支持 Godot 可在运行时加载的 MP3、Ogg Vorbis 和 WAV 文件。导入后的文件保存至 `user://custom_bgm/`；此位置属于玩家数据，不会写入项目的 `res://` 资源目录。

曲目配置保存为独立元数据，至少包含：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定的本地曲目 ID |
| `display_name` | 玩家看到的曲名，默认取文件名 |
| `local_path` | `user://custom_bgm/` 下的相对位置 |
| `format` | 音频格式 |
| `file_hash` | 用于检测文件是否被替换或损坏 |
| `bpm` | 最终确认的每分钟节拍数 |
| `first_beat_offset_sec` | 音频开始到第一拍的秒数 |
| `analysis_confidence` | 自动 BPM 识别的可信度 |
| `created_at` | 导入时间 |

不保存外部绝对路径作为唯一依据，避免玩家移动、重命名或删除源文件后曲目失效。

## 5. BPM 与首拍校正规则

自动识别仅用于提供初始值，最终用于战斗的 BPM 必须是玩家确认后的数值。

- 建议的初始检测范围为 70–200 BPM。
- 若检测得到的 BPM 是实际节奏的一半或两倍，玩家可一键减半或加倍。
- 允许以小数 BPM 微调，以适配录音速度轻微偏差。
- 首拍偏移独立于 BPM 保存。它解决“节奏速度正确、但第一拍没有对齐”的问题。
- 玩家未完成校正时，曲目仍可游玩，但 UI 应提示节奏可能不准确。

战斗中的节拍计算概念为：

`当前拍数 = (音乐已播放秒数 - 首拍偏移秒数) × BPM ÷ 60`

拍点、判定、敌人节奏行为和演出必须读取同一份战斗节拍时钟，不能各自按帧计时。

## 6. 自动分析策略

自动 BPM 分析应在导入后或玩家主动点击“重新分析”时执行，不应在每场战斗内实时重新猜测。

建议策略：

1. 提取低频与中低频的能量变化，寻找鼓点等瞬态峰值。
2. 根据峰值间隔生成 BPM 候选。
3. 对候选进行统计，选出最稳定的节奏并计算可信度。
4. 对半拍、双拍结果进行归一化，并保留用户校正入口。

变速曲、自由节奏音乐、现场录音和鼓点不明显的音乐可能没有单一可靠 BPM。这些场景必须允许玩家直接输入 BPM，或在后续版本扩展为“分段节奏图”模式。

## 7. 错误处理与边界

- 格式不支持、文件损坏或无法解码时，不创建曲目记录，并给出明确错误提示。
- 文件过大时阻止导入或要求玩家确认，避免设备存储和内存压力。
- 导入复制失败时清理未完成数据，不留下可被曲库读取的半成品记录。
- 用户删除已导入文件后，在曲库中标记为“文件缺失”，不允许进入战斗。
- 同一文件重复导入时，根据文件校验值提示复用或另存，避免无意义副本。
- 删除曲目应只删除 `user://custom_bgm/` 下该曲目的副本与对应元数据，不能操作玩家原始文件。

## 8. 版权与隐私提示

本功能只处理设备本地文件，游戏不应默认上传、共享、打包或公开玩家音乐。界面应提示玩家：仅导入其拥有使用权的音乐；开发者不因“允许本地导入”而获得用户曲目的发行权。

## 9. 后续实施拆分

1. **曲库基础**：导入、复制、列出、删除、文件状态检查。
2. **手动节奏配置**：试听、BPM 输入、首拍点击校正、战斗选择。
3. **自动 BPM 分析**：离线分析、可信度、失败回退。
4. **战斗接入**：将战斗全部节奏规则接到统一节拍时钟。
5. **体验完善**：波形预览、节拍网格、重分析、曲目收藏和筛选。

## 10. 验收标准（后续实现时使用）

- 玩家可导入一首有效的 MP3、Ogg Vorbis 或 WAV，并在重启游戏后仍可看到它。
- 玩家可手动设置 BPM 与首拍偏移，并在战斗中稳定生效。
- 自动识别失败不会阻止玩家手动配置和游玩。
- 缺失、损坏和不支持的文件不会导致崩溃，也不会留下不可用的曲目配置。
- 删除导入曲目不会删除玩家在游戏外的原始音乐文件。
