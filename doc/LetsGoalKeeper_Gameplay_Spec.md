# LetsGoalKeeper 玩法基准文档

> 用途：记录 Unity 原型中已经实现或已经配置的玩法，作为后续 Godot 4 + GDScript 重写时的基准。
>
> 文档依据：Unity `Assets` 目录中的场景、Prefab、脚本、ScriptableObject、UXML 与 Addressables 配置。
>
> 版本状态：原型审计版。文中“当前实现”代表代码/资源的实际状态；“目标规则”代表迁移时建议保留的玩法语义；“待确认”代表原工程存在冲突、占位值或未完成内容。

## 1. 游戏定位

`LetsGoalKeeper` 是一款足球主题的单人 2D Roguelike 卡牌构筑游戏。

玩家通过路线地图进入不同房间，在回合制战斗中打出射门、防守和能力卡牌，对抗动物守门员/敌人。战斗胜利后获得新卡牌与战利品，逐步强化牌组，击败章节 Boss 后进入下一章。

### 核心体验

- 足球动作包装的卡牌战斗：直球、香蕉球、挑射、随机射门等卡牌对应不同足球飞行动画。
- 回合制资源管理：使用能量打牌，用护盾承受敌人反击。
- 同类卡连续使用可累计连击点，并释放对应类型的主动技能。
- 在分支地图上选择普通战斗、精英战斗、休息房与 Boss 房。
- 通过卡牌和战利品构筑本局成长路线。

## 2. 单局核心循环

1. 从主菜单开始新游戏。
2. 生成当前章节的路线地图。
3. 从可进入节点中选择一个房间。
4. 如果是战斗房，生成对应章节和类型的敌人。
5. 进入玩家回合，抽取手牌并恢复能量。
6. 玩家拖拽并打出卡牌，结算足球动画和卡牌效果。
7. 玩家主动结束回合。
8. 敌人按照提前展示的意图行动。
9. 双方未死亡则进入下一玩家回合。
10. 战斗胜利后选择卡牌奖励和战利品奖励。
11. 返回地图，已进入房间标记为完成，并解锁与其相连的下一层房间。
12. 击败 Boss 后进入下一章并生成新地图。
13. 击败第三章 Boss 后完成整局；玩家死亡则本局失败。

## 4. 地图系统

### 4.1 地图结构

当前每章地图配置为三层：

| 层级 | 房间数量 | 当前房间池 |
| --- | ---: | --- |
| 第1层 | 随机2～3个 | 普通战斗 |
| 第2层 | 随机2～3个 | 普通战斗或精英战斗 |
| 第3层 | 固定1个 | Boss |

代码已经支持休息房，但当前 `MapConfigSO` 没有把休息房加入随机地图。

### 4.2 连线规则

- 每个房间至少连接到下一层的一个房间。
- 下一层所有房间至少应有一条来自上一层的连线。
- 第一层所有房间初始可进入。
- 玩家完成某个房间后：
  - 当前房间变为“已访问”。
  - 同层其他房间变为“锁定”。
  - 当前房间连接的下一层房间变为“可进入”。
- 玩家不能回到同层另一条路线。

### 4.3 房间状态

| 状态 | 含义 |
| --- | --- |
| `Locked` | 不可进入 |
| `Visited` | 已完成 |
| `Attainable` | 当前可选择 |

### 4.4 房间类型

| 类型 | 行为 |
| --- | --- |
| 普通战斗 | 生成当前章节普通敌人 |
| 精英战斗 | 生成当前章节精英敌人 |
| Boss | 生成当前章节 Boss |
| 休息房 | 允许玩家治疗一次，然后返回地图 |

休息房当前治疗量为20点，不超过最大生命。

## 5. 战斗系统

### 5.1 战斗形式

- 当前每场战斗只生成一个敌人。
- 玩家和敌人轮流行动。
- 玩家回合没有倒计时限制；配置中的2秒是回合切换延迟。
- 敌人回合开始前，玩家可以看到敌人的行动意图与预计数值。
- 玩家主动点击“结束回合”后，敌人执行当前意图。

### 5.2 玩家基础属性

| 属性 | 当前配置 | 说明 |
| --- | ---: | --- |
| 最大生命 | 100 | 新游戏恢复至满血 |
| 基础力量倍率 | 1.0 | 影响伤害计算 |
| 最大能量 | **存在冲突** | `PlayerMana`资源为3，但玩家Prefab为100，运行代码会采用100 |
| 主动技触发门槛 | 3连击点 | 同类卡连续使用累积 |

Godot 版开始开发前应确认每回合能量究竟是3还是100。结合全部卡牌费用均为1、资源上限为3，设计意图更像是每回合3点。

### 5.3 回合流程

#### 玩家回合开始

1. 恢复本回合能量。
2. 抽取3张牌。
3. 更新敌人下一次行动意图。
4. 玩家可以连续打牌或释放主动技能。
5. 玩家点击结束回合。

#### 玩家回合结束

1. 未使用的手牌全部进入弃牌堆。
2. 切换至敌人回合。

#### 敌人回合

1. 敌人清空自身护盾。
2. 执行当前攻击、防御、治疗或削弱意图。
3. 意图隐藏。
4. 延迟后回到玩家回合。

> 待确认：当前代码没有明确在玩家回合开始时清空玩家护盾，也没有把力量持续回合的递减方法连接进事件。Godot版需要明确“护盾是否每回合清零”和“Buff在谁的回合结束时减1”。

### 5.4 伤害与护盾

基础伤害流程：

```text
卡牌基础伤害
+ 全类型伤害加成
+ 对应射门类型伤害加成
× 力量倍率
= 最终攻击值
```

护盾结算：

```text
生命伤害 = max(最终攻击值 - 当前护盾, 0)
剩余护盾 = max(当前护盾 - 最终攻击值, 0)
```

- 护盾优先承受伤害。
- 治疗不能超过最大生命。
- 敌人的攻击会在基础数值上乘以约0.8～1.2的随机系数，再乘力量倍率。
- 敌人意图界面应显示此次随机后的预计攻击值。

### 5.5 力量与虚弱

当前设计语义：

- 基础力量为1.0倍。
- 助跑类Buff将力量提升到1.5倍并持续若干回合。
- 虚弱类Debuff将力量降到0.5倍并持续若干回合。

当前代码的力量上限写反，会使正向力量继续叠加；Godot版建议先按“固定1.5倍、不可继续叠倍率，只刷新或叠加持续回合”实现，除非后续重新确认。

## 6. 卡牌系统

### 6.1 牌堆规则

- 新游戏牌库当前配置为4张完全相同的“香蕉球”。
- 战斗开始时，将本局牌库复制到抽牌堆并洗牌。
- 玩家回合开始抽3张。
- 每打出一张牌，效果和动画结束后：
  - 该牌进入弃牌堆。
  - 立即抽1张补回原手牌位置。
- 玩家结束回合时，剩余手牌全部弃掉。
- 抽牌堆为空时，将弃牌堆洗回抽牌堆。
- 卡牌费用不足时不可打出。
- 当前全部卡牌费用均为1。

### 6.2 卡牌类型

| 类型 | 作用 | 对应主动技 |
| --- | --- | --- |
| 攻击 | 对敌人造成伤害，并播放射门表现 | 超级攻击 |
| 防御 | 增加护盾 | 超级防御 |
| 能力 | 治疗、回能、力量或削弱等 | 超级能力 |

### 6.3 射门类型

| 类型 | 表现 |
| --- | --- |
| 直球 | 球沿轻微随机偏移的路径快速飞向敌人 |
| 香蕉球 | 随机向左或向右画较大弧线 |
| 挑射 | 球体先放大、走高弧线，再落向敌人 |
| 随机射门 | 在直球、挑射、左香蕉球、右香蕉球之间随机 |

足球飞行目前主要承担表现作用，伤害在动画延迟后直接结算，不使用真实物理碰撞判定。

### 6.4 当前卡牌清单

| 资源名 | 类型 | 射门 | 当前效果 | 品级 |
| --- | --- | --- | --- | --- |
| 香蕉球 | 攻击 | 香蕉球 | 造成6伤害 | 普通 |
| 射门 | 攻击 | 直球 | 造成6伤害 | 普通 |
| 挑射 | 攻击 | 挑射 | 造成6伤害 | 普通 |
| 橄榄球 | 攻击 | 随机 | 造成6伤害 | 普通 |
| attack | 攻击 | 随机 | 连续造成5次2伤害 | 普通 |
| 一组射门 | 攻击 | 随机 | 连续造成5次2伤害 | Boss |
| 双向香蕉球 | 攻击 | 香蕉球 | 连续造成2次3伤害 | Boss |
| 嗜血球 | 攻击 | 直球 | 造成6伤害，然后固定治疗3点 | 普通 |
| 尖刺球 | 攻击 | 香蕉球 | 自身先受3伤害，再对敌人造成6伤害 | Boss |
| 爆炸球 | 攻击 | 直球 | 50%概率自身受3伤害并中断；否则造成12伤害 | Boss |
| 能量射门 | 攻击 | 直球 | 基础6伤害；每点剩余能量增加2伤害 | Boss |
| 手套 | 防御 | 无 | 增加6护盾 | 普通 |
| heal | 能力 | 无 | 治疗6点 | 普通 |
| 佳得乐 | 能力 | 无 | 治疗6点 | 普通 |
| 毛巾 | 能力 | 无 | 当前效果资源恢复2能量，但文本写恢复6 | 普通 |
| 助跑 | 能力 | 无 | 获得正向力量，配置持续2回合 | 普通 |
| 虚弱 | 能力 | 无 | 令目标进入虚弱，配置持续2回合 | 普通 |

> 多段攻击会为每个伤害效果分别播放一次射门动画。

## 7. 连击与主动技能

### 7.1 连击规则

- 第一次打牌时，连击点设为1。
- 连续使用相同类型的卡牌，连击点+1。
- 换用另一种类型的卡牌，连击点重置为1，并切换主动技能类型。
- 连击点达到3后，可以主动点击技能按钮释放当前类型技能。
- 释放后连击点清零，主动技能类型清空。
- 进入新房间时连击点清零。

### 7.2 主动技能

| 技能 | 当前公式 | 表现 |
| --- | --- | --- |
| 超级攻击 | `(10 + 全伤害加成) × 连击点 × 力量倍率` | 播放超级直球，对敌人造成技能伤害 |
| 超级防御 | `6 × 连击点` | 增加玩家护盾 |
| 超级能力 | `1 × 连击点`作为持续回合参数 | 给玩家施加正向力量 |

当前三个主动技能资源的`skillType`字段都配置成了攻击类型，但管理器通过三个独立引用选择技能。Godot版应修正为攻击、防御、能力各自独立。

## 8. 敌人系统

### 8.1 通用行为

- 每个敌人拥有生命、护盾、力量和行动列表。
- 普通/精英敌人从随机的行动下标开始，之后按行动列表循环。
- Boss每回合随机选择一个行动。
- 行动类型包括攻击、防御、治疗和施加虚弱。
- 敌人攻击具有约±20%的随机浮动。

### 8.2 特殊敌人规则

| 敌人 | 特殊规则 |
| --- | --- |
| 熊 | 受到主动技能伤害时，技能伤害减半 |
| 乌龟 | 每次受到伤害时，玩家同时受到1点伤害 |
| 企鹅 | 行动数据包含吸血式伤害与虚弱 |
| 其他敌人 | 目前主要通过不同的行动表区分 |

### 8.3 当前章节配置

| 第3章 | 机器人（列表中重复3次） | 蛇 | 螳螂 |

其他已经存在但当前未加入章节池的敌人：苍蝇、乌龟、斑马、章鱼。

## 9. 战利品系统

### 9.1 奖励规则

- 普通战斗从普通奖励池抽取。
- Boss战斗从Boss奖励池抽取。
- 奖励界面各展示3个候选项。
- 卡牌可以重复获得，重复卡牌增加牌库中的数量。
- 战利品原则上不可重复获得，通过`isOwned`排除已拥有战利品。
- 当前胜利面板允许分别领取一张卡牌和一件战利品，然后返回地图；并不是二选一。

### 9.2 当前战利品

| 战利品 | 品级 | 当前效果 |
| --- | --- | --- |
| 金靴 | 普通 | 所有射门伤害+1 |
| 金靴1 | 普通 | 所有射门伤害+1 |
| 金靴2 | 普通 | 所有射门伤害+1，当前显示名为占位字符串 |
| 葡萄牙7号 | Boss | 直球伤害+1 |
| 阿根廷10号 | Boss | 香蕉球伤害+1 |
| 角旗杆 | Boss | 文本为“添加两张角球到牌库”，当前没有配置实际效果 |

代码中已经存在“挑射伤害+1”的效果类型，但没有战利品资源使用它。

## 10. 胜负与章节推进

### 10.1 普通/精英战斗胜利

- 敌人死亡后停止回合系统。
- 显示胜利界面。
- 玩家可以领取普通卡牌奖励和普通战利品奖励。
- 返回地图后更新当前路线。

### 10.2 Boss胜利

- 第1、2章Boss死亡后：
  - 清空旧地图数据。
  - 显示Boss胜利界面。
  - 章节数+1。
  - 返回时生成下一章地图。
- 第3章Boss死亡后应判定整局胜利。

当前代码在第3章Boss死亡后触发的是`GameOverEvent`，没有独立最终胜利界面；Godot版需要新增“通关”状态与结算界面。

### 10.3 失败

- 玩家生命降至0时停止战斗。
- 显示失败界面。
- 玩家可返回主菜单。
- 新游戏应重置生命、能量、牌库、战利品、伤害加成、章节和地图。

## 11. 输入规则

### 桌面端

- 鼠标点击地图房间。
- 鼠标拖拽卡牌，拖到执行线以上后释放即使用。
- 点击按钮结束回合、释放主动技能、选择奖励或休息。

### 手机端目标规则

- 单指点击地图房间。
- 单指拖拽卡牌，与鼠标使用相同判定。
- UI按钮支持触摸。
- 拖拽判定不能直接依赖鼠标坐标，应统一使用Godot的指针/触摸事件。
- 关键按钮和卡牌需要适配安全区与不同纵横比。

## 12. Godot重写时必须分离的数据

### 固定定义数据

以下内容可使用Godot `Resource`：

- 卡牌名称、费用、类型、图片和效果列表
- 战利品名称、品级和效果
- 敌人基础属性和行动列表
- 房间类型和地图生成配置
- 技能基础数值

### 本局运行数据

以下内容不能写回固定Resource，应存放在`RunState`或战斗实例中：

- 当前生命、护盾、能量和连击点
- 当前牌库、抽牌堆、弃牌堆和手牌
- 已拥有战利品
- 当前章节与地图节点状态
- Buff剩余回合
- 当前敌人行动和随机系数
- 卡牌是否中断后续效果
- 临时伤害加成

## 13. 首个可玩版本验收标准

Godot第一阶段只需实现以下闭环：

1. 从测试战斗场景启动。
2. 玩家100生命、每回合恢复固定能量。
3. 初始牌库至少包含直球、香蕉球、防御和治疗。
4. 每回合抽3张，打牌后补1张。
5. 卡牌能通过鼠标和触摸拖拽使用。
6. 攻击卡播放对应足球动画后结算伤害。
7. 敌人显示意图并在敌人回合执行。
8. 护盾、治疗、力量、虚弱正确结算。
9. 同类型卡牌累计连击点，3点以上可释放主动技。
10. 玩家或敌人死亡后正确显示胜负界面。

达到以上10项后，再迁移地图、奖励、三章内容和平台功能。

## 15. 已知原型问题：不要当作玩法复制

- 卡牌奖励随机后，有一条路径会从错误的总卡池下标取卡。
- 特定射门伤害加成的Setter实际写入了全局伤害字段。
- 正向力量倍率的上限判断方向写反。
- 卡牌、战利品和地图运行状态会直接修改ScriptableObject资源。
- 玩家能量上限存在3与100冲突。
- 部分运行脚本引用了Editor或测试命名空间。
- 第2章精英池为空，但地图可能生成精英房。
- 多个敌人生命值和道具名称仍是测试占位值。
- 第三章Boss死亡触发失败事件。
- 玩家护盾和Buff回合的重置/递减规则没有完整接入事件。
- 当前Unity拖拽依赖鼠标位置，不能直接视为手机端已经完成。

这些问题在Godot重写时应按本玩法文档重新实现，而不是逐行翻译旧代码。
